## Features Implemented

### 1️⃣ Case List (Pipeline View) - `/dashboard/cases`

**Features:**
- Lists all cases belonging to the logged-in user
- Displays: client name, case type, loan size, current stage, last updated date
- Filter/group by pipeline stage dropdown
- Pipeline summary showing count per stage
- "Create Case" button
- "View" button for each case

**Supabase Query:**
```typescript
supabase
  .from('cases')
  .select('*')
  .eq('created_by', user.id)
  .order('updated_at', { ascending: false })
  // Optional filter by pipeline stage
  .eq('pipeline', filterStage)
```

**RLS:** Respects existing RLS - only shows cases created by logged-in user

---

### 2️⃣ Create Case - `/dashboard/cases/new`

**Required Inputs:**
- Case Type (Refinancing or Purchase) - **Required**
- Client Name - Optional
- Loan Size - Optional

**Default Values:**
- `pipeline` → "Touched Base"
- `created_by` → Current user ID
- `created_at` / `updated_at` → Auto-generated by Supabase

**Supabase Query:**
```typescript
supabase
  .from('cases')
  .insert({
    case_type: formData.case_type,
    client_name: formData.client_name || null,
    loan_size: formData.loan_size ? parseFloat(formData.loan_size) : null,
    pipeline: 'Touched Base',
    created_by: user.id
  })
  .select()
  .single()
```

**Flow:**
1. User fills minimal form
2. Case created with default pipeline stage
3. Redirects to case detail page for further editing

---

### 3️⃣ Case Detail Page - `/dashboard/cases/[id]`

**Features:**
- View/Edit mode toggle
- Displays all case information
- Editable fields based on case type
- Pipeline stage selector
- Closure fields (only visible when "Closed Won")

**Case Type Specific Fields:**

**Refinancing:**
- Current Bank
- Existing Loan Amount
- Lock-in End Date

**Purchase:**
- Property Address
- Property Type (HDB, Condo, Landed, etc.)
- Purchase Price

**Supabase Query (Load):**
```typescript
supabase
  .from('cases')
  .select('*')
  .eq('id', caseId)
  .eq('created_by', user.id)
  .single()
```

**Supabase Query (Update):**
```typescript
supabase
  .from('cases')
  .update({
    ...updates,
    updated_at: new Date().toISOString()
  })
  .eq('id', caseId)
```

### 4️⃣ Closure Logic (Closed Won)

**Behavior:**
- Closure fields **only appear** when pipeline stage is "Closed Won"
- Fields are not required in earlier stages
- Green-highlighted section for visual distinction

**Closure Fields:**
- Package Details (e.g., "DBS 2-Year Fixed")
- Interest Rate (%)
- Tenure (years)
- Subsidy Amount ($)
- Clawback End Date
- Remarks (textarea)

**Implementation:**
```typescript
const isClosedWon = caseData.pipeline === 'Closed Won'

// Conditional rendering
{isClosedWon && (
  <div>
    {/* Closure fields form */}
  </div>
)}

// Only save closure fields when Closed Won
if (caseData.pipeline === 'Closed Won') {
  updates.package_details = caseData.package_details
  updates.interest_rate = caseData.interest_rate
  // ... other closure fields
}
```

## Pipeline Stages

The system supports 7 pipeline stages:
1. **Touched Base** (default for new cases)
2. **Sent Docs**
3. **Pending Submission**
4. **Submitted**
5. **Approved**
6. **Closed Won** (triggers closure fields)
7. **Closed Lost**

---

## UX Flow

### Creating a Case
1. User clicks "Create Case" from dashboard or cases list
2. Fills minimal form (case type required, others optional)
3. Case created with "Touched Base" stage
4. Redirected to case detail page
5. Can add more details and move through pipeline

### Managing a Case
1. User views case list
2. Filters by pipeline stage if needed
3. Clicks "View" on a case
4. Sees all case details in read-only mode
5. Clicks "Edit" to modify
6. Updates fields (including pipeline stage)
7. Clicks "Save" to persist changes
8. If moved to "Closed Won", closure fields appear
9. Fills closure details and saves

### Pipeline Movement
- User can move case between any stages
- When moved to "Closed Won", closure section appears
- If moved away from "Closed Won", closure fields hidden (but data preserved)

## Database Schema Assumptions

The implementation assumes the `cases` table has these columns:

**Core Fields:**
- `id` (uuid, primary key)
- `created_at` (timestamp)
- `updated_at` (timestamp)
- `created_by` (uuid, foreign key to auth.users)

**Basic Info:**
- `client_name` (text, nullable)
- `case_type` (text: 'Refinancing' | 'Purchase')
- `loan_size` (numeric, nullable)
- `pipeline` (text: pipeline stage)

**Refinancing Fields:**
- `current_bank` (text, nullable)
- `existing_loan` (numeric, nullable)
- `lock_in_date` (date, nullable)

**Purchase Fields:**
- `property_address` (text, nullable)
- `property_type` (text, nullable)
- `purchase_price` (numeric, nullable)

**Closure Fields:**
- `package_details` (text, nullable)
- `interest_rate` (numeric, nullable)
- `tenure` (integer, nullable)
- `subsidy` (numeric, nullable)
- `clawback_end_date` (date, nullable)
- `closure_remarks` (text, nullable)
